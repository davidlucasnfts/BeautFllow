Proposta — Agendamento sem atrito

19/10/2026 · Aguardando autorização · Nenhum código alterado

Solicitação do David: hoje, para agendar, o dono precisa antes cadastrar cliente, profissional e serviço em telas separadas. Preocupação: o usuário pode achar trabalhoso/estranho e desistir. Pesquisa de mercado: cadastro prévio de serviço e profissional é padrão (Booksy, Trinks, Fresha — é setup único), mas cliente os apps bons criam na hora, sem sair do agendamento.

Item 1 — Cadastrar cliente sem sair do agendamento ⭐ (principal)

O que muda na tela: no campo "Cliente" do Novo Agendamento, ao digitar um nome que não existe, aparece a opção "+ Cadastrar Maria Silva" logo abaixo da busca.
Cliente ┌─────────────────────────────────────────────┐ │ maria silva │ ├─────────────────────────────────────────────┤ │ Nenhum cliente encontrado. │ │ ┌─────────────────────────────────────────┐ │ │ │ ＋ Cadastrar "maria silva" │ │ ← clique abre o mini-form │ └─────────────────────────────────────────┘ │ └─────────────────────────────────────────────┘
Mini-formulário (dentro do próprio dialog, sem sair da tela):
  • Nome — já vem preenchido com o que foi digitado
  • Telefone — máscara (99) 99999-9999 (padrão do app)
  • Checkbox LGPD — "Cliente autorizou o uso dos dados" (mesmo checkbox do cadastro completo, obrigatório pra cumprir a regra de consentimento que já existe)
  • Botão verde "Cadastrar e selecionar" — cria o cliente e já preenche o campo do agendamento
Tempo total pro dono: ~10 segundos. O cadastro completo (e-mail, aniversário, observações) continua existindo na aba Cliente pra quem quiser completar depois.
┌─ Cadastrar cliente rápido ─────────────────┐ │ Nome [ Maria Silva ] │ │ Telefone [ (98) 98765-4321 ] │ │ ☑ Cliente autorizou o uso dos dados (LGPD)│ │ │ │ [ ✓ Cadastrar e selecionar ] │ └─────────────────────────────────────────────┘
Backend: nenhum endpoint novo — reutiliza o client.create que já existe (já valida, já tem audit log). O frontend chama, recebe o id e seleciona automaticamente.

Item 1b — Lembrete de completar cadastro (data de nascimento) 🎂

Ponto do David: o cliente criado no cadastro rápido fica sem data de nascimento — e esse dado vai alimentar relatórios e mensagens de WhatsApp com promoções/aniversário. Precisa de um jeito de lembrar de preencher depois.
O que muda na tela (aba Cliente):
  • Cliente sem data de nascimento ganha um badge âmbar "Sem nascimento" na lista (visível de relance, no padrão dos badges de status que já existem)
  • Quando houver pelo menos 1 nesse caso, aparece um aviso no topo da lista: "🎂 X clientes sem data de nascimento — complete para campanhas de aniversário" com botão "Ver" que filtra a lista só pra esses clientes
  • Pra preencher: clicar no cliente → Editar (o formulário completo já tem o campo de nascimento — zero tela nova)
Por que assim (e não popup obrigatório): obrigar o preenchimento na hora quebraria o fluxo rápido (o cliente está na frente do dono querendo agendar). O badge + filtro deixa a pendência visível sem atrapalhar — e cria a base pra futura campanha automática de aniversário no WhatsApp (já está no backlog de lembretes automáticos).

Item 2 — Assistente de primeiro uso (até 3 serviços + 3 profissionais, com opção de desligar)

Problema que resolve: o dono novo abre a agenda vazia, clica "Novo agendamento" e trava (não tem serviço nem profissional). Em vez da frustração, ele vê um guia — e o guia incentiva o mínimo viável de catálogo (3+3), não só 1+1.
O que muda na tela: enquanto o salão não tiver 3 serviços E 3 profissionais (e o guia não estiver desativado), a agenda mostra um card-checklist no topo com progresso:
┌─ Configure seu StudioFlow ──────────────────────────────┐ │ │ │ Serviços ✅✅⬜ 2 de 3 [ + Cadastrar ] │ │ Profissionais ✅⬜⬜ 1 de 3 [ + Cadastrar ] │ │ [ Sou eu mesmo ] │ │ │ │ Dica: 3+3 cobre o básico (ex: Corte, Escova, Barba) │ └──────────────────────────────────────────────────────────┘
Comportamento:
  • Os botões abrem os dialogs que já existem (Serviço, Profissional) — nenhuma tela nova
  • "Sou eu mesmo" cria o profissional com o nome do dono logado em 1 clique (comissão 0%, editável depois) — conta como 1 dos 3
  • Progresso atualiza na hora (✅ a cada cadastro); ao chegar em 3+3, o card some sozinho
  • Opção de desligar: nova chave em Configurações — toggle "Mostrar guia de primeiros passos" (padrão: ligado). Desligou, o card não aparece mais mesmo sem completar; ligou de volta, ele retorna. Fica no JSON salons.settings — sem migration

O que eu NÃO recomendo fazer

Serviço e profissional "inline" no agendamento: serviço tem preço, duração e categoria; profissional tem comissão e horários. Um mini-form disso ficaria ruim e geraria cadastros incompletos. O checklist (item 2) resolve o caso real, porque serviço/profissional se cadastra uma vez só — diferente do cliente, que nasce todo dia.

Esforço: médio. Item 1 = opção no combobox de cliente + mini-form (reusa client.create). Item 1b = badge + filtro na lista de clientes (só frontend, campo birthDate já existe). Item 2 = card-checklist com progresso 3+3 derivado de dados + botão "Sou eu mesmo" + toggle no JSON salons.settings. Sem migration, sem tabela nova, sem mudança visual nas demais telas.

Me diz: "pode fazer" → implemento os 3 itens (1, 1b e 2). Ou ajusta o que quiser antes.
